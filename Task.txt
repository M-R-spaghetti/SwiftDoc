Краткое содержание
Технические характеристики 1. Цель проекта Разработать мобильное приложение, позволяющее пациентам: Легко записываться на прием в клинику Выбирать врача Оплачивать услуги онлайн или в клинике Получать автоматические уведомления Просматривать историю своих приемов Получать доступ к информации о клинике Использовать программу лояльности Управлять своим профилем и профилями членов семьи Получать напоминания о плане лечения Приложение должно быть: Быстрым Безопасным Удобным для пользователя Визуально соответствовать предоставленному прототипу дизайна
 2. Платформы Приложение должно работать на: iOS Android Рекомендуемые технологии: Кроссплатформенный фреймворк: Flutter или React Native Бэкенд: Node.js Firebase Supabase База данных: PostgreSQL или Firebase Firestore 
3. Поддержка языков Приложение должно поддерживать три языка: грузинский Английский Русский Требования: Весь текст должен быть готов к переводу Пользователи должны иметь возможность изменить язык в разделе «Профиль» Изменение языка должно мгновенно применяться ко всему приложению
 4. Аутентификация Приложение должно включать аутентификацию OTP с использованием номера телефона. Процесс входа: Номер телефона SMS Код OTP Требования к OTP: Одноразовый Ограниченный по времени Дополнительные методы аутентификации: Пользователи должны иметь возможность включить биометрическую аутентификацию для более быстрого входа: Face ID (iOS) Touch ID (iOS) Отпечаток пальца (Android) Биометрическая аутентификация должна использоваться только после того, как пользователь хотя бы раз вошел в систему.
 5. Экран регистрации Приложение должно включать отдельный экран регистрации для новых пользователей. Последовательность действий пользователя: Экран входа → Экран регистрации → SMS-подтверждение → Страница меню Поля формы регистрации: Имя Фамилия Номер удостоверения личности Номер телефона Адрес электронной почты Адрес проживания Обязательные поля: Имя Фамилия Номер телефона Требования к проверке: Проверка формата номера телефона Проверка формата электронной почты Проверка пустых полей Процесс регистрации: После заполнения формы: Пользователь получает SMS-код Пользователь вводит код OTP Учетная запись становится активной Требования к пользовательскому интерфейсу: Экран регистрации должен быть: Визуально согласован с экраном входа Минималистичным Простым и быстрым в заполнении 
6. Восстановление пароля Несмотря на использование OTP-аутентификации, система должна включать функцию восстановления учетной записи. Экран входа должен включать: Забыли пароль. Последовательность действий пользователя: Забыли пароль → Введите номер телефона или адрес электронной почты → Получите код подтверждения → Введите OTP → Сбросить пароль. Требования: OTP по SMS или электронной почте. Пароль не менее 8 символов. Не менее одной цифры. Не менее одной заглавной буквы.
 7. Главное меню. После входа в систему пользователь перенаправляется на страницу меню. Пункты меню: Главная. Профиль. Моя семья. Новости и советы. План лечения. История обслуживания. Карта лояльности. Запись на прием. Выход. 
8. Главная страница. Главная страница должна включать: Предстоящие приемы. Если у пользователя есть записанный прием, отобразите: Время приема у врача. Кнопки действий: Перенести. Отменить прием. Добавить в календарь. Кнопка быстрого действия: Записаться на прием. Раздел «Акции»: Акции и объявления клиники.
9. Семейный аккаунт / Профиль ребенка. Приложение должно позволять пользователям управлять профилями членов семьи. Пользователи должны иметь возможность добавлять: детей, членов семьи. Профиль ребенка должен включать: имя, фамилию, дату рождения, идентификационный номер (необязательно). Пользователи должны иметь возможность: записывать ребенка на прием, просматривать историю посещений ребенка, просматривать план лечения ребенка. Приложение должно включать переключатель профилей для переключения между профилями. 
10. Страница профиля Пользователи должны иметь возможность: Просматривать личную информацию Редактировать личную информацию Изменять язык Управлять настройками уведомлений Включать или отключать биометрический вход 
11. Новости и советы В этом разделе должны отображаться: Новости клиники Советы по стоматологии Акции Функции: Список новостей Страница с подробной статьей 
12. Страница врачей Список врачей должен включать: Фото Имя Специализация Краткое описание Врачи: Нино Беридзе – Ортодонт Эка Чихрадзе – Терапевт Мераб Бибичадзе – Челюстно-лицевой хирург 
13. Страница профиля врача Страница профиля врача должна включать: Фото Полное имя Специализация Опыт Языки Услуги Отзывы о враче должны включать: Рейтинг в звездах Средний рейтинг Количество отзывов
 14. Запись на прием (процесс записи) Шаг 1 Выберите услугу Примеры: Консультация Ортодонтия Хирургия Чистка зубов Шаг 2 Выберите врача Шаг 3 Выберите дату и время Должно включать: Календарь Доступные временные интервалы Шаг 4 Подтверждение Шаг 5 Оплата Способы оплаты: Оплата в клинике Оплата картой Apple Pay Google Pay
 15. Отмена и перенос записи Пользователи Приложение должно иметь возможность: Отменять запись на прием Переносить запись на прием Ограничения: Отмена допускается не менее чем за 12 часов до приема Перенос записи требует выбора нового временного интервала
 16. Интеграция с календарем После записи на прием пользователи должны иметь возможность: Добавить в календарь Приложение должно поддерживать автоматическую интеграцию с: Календалом iOS Календаром Google Событие в календаре должно включать: Врача Местоположение клиники Дата и время Тип услуги 17. План лечения и интеллектуальные напоминания Приложение должно включать систему планирования лечения. Врачи или администраторы должны иметь возможность назначать планы лечения пациентам. Примеры: Ортодонтическое лечение Лечение винирами Чистка зубов Отслеживание прогресса ортодонтического лечения Для пациентов с брекетами система должна отображать информацию о прогрессе лечения. Пример: Продолжительность лечения Оставшееся время Пример: Всего 12 месяцев Осталось 6 месяцев Напоминание о чистке зубов Если пациент прошел чистку зубов, система должна автоматически отправлять напоминание: Через 6 месяцев. Пример уведомления: «Пора на следующую чистку зубов». 
18. Уведомления. Приложение должно отправлять: SMS-сообщения, подтверждение записи на прием, напоминания о записи на прием, push-уведомления, рекламные акции, напоминания о лечении, обновления клиники.
 19. История обслуживания. Пользователи должны иметь возможность просматривать: дату посещения, врача, оказанную услугу, цену.
 20. Карта лояльности. Приложение должно включать цифровую программу лояльности. Отображение: баланс баллов, уровни статуса: серебро, золото, платина. 21.Дизайн. Приложение должно соответствовать предоставленному дизайну пользовательского интерфейса. Цвета: Основной #C2188B, Вторичный #8E2A8C, Белый фон.
 22. Безопасность. Требуемые стандарты безопасности: HTTPS, Безопасное хранение данных, Безопасная аутентификация, Соответствие GDPR. 
23. Панель администратора. Должна быть включена веб-панель администратора. Функции: Управление врачами, Управление записями на прием, Управление планами лечения, Добавление новостей и акций, Управление бонусными баллами.
 24. Результаты работы разработчика. Разработчик должен предоставить: iOS-приложение, Android-приложение, Бэкенд-систему, Панель администратора, Исходный код, Техническую документацию.
 25. Сроки проекта. Версия MVP: 6–10 недель, Полная версия: 3–месяца.
